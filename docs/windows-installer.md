# Windows EXE installer (no PowerShell)

`rustfetch-setup.exe` is a plain, double-clickable installer for Windows
x86_64. It is an alternative to the PowerShell one-liner in the README for
people who cannot or do not want to run `powershell.exe` / `irm ... | iex`.
It needs no execution-policy change and no administrator rights.

## Download and run

1. Open the [latest release](https://github.com/hakergeniusz/rustfetch/releases/latest)
   and download **`rustfetch-setup.exe`**.
2. Double-click it. A console window shows each step (download, hash check,
   install, PATH update).
3. Open a **new** terminal and run `rustfetch`.

Direct link, if you prefer a browser or `curl`/`wget`:

```
https://github.com/hakergeniusz/rustfetch/releases/latest/download/rustfetch-setup.exe
```

By default the binary is installed to:

```
%LOCALAPPDATA%\Programs\rustfetch\rustfetch.exe
```

and that directory is added to the **user** PATH (`HKCU\Environment`). The
system PATH is never touched, so no "Run as administrator" prompt appears.

## SmartScreen / unsigned binary

The installer is **not code-signed**. On a fresh download Windows Defender
SmartScreen may show a blue "Windows protected your PC" screen:

1. Click **More info**.
2. Click **Run anyway**.

Some browsers also add a "blocked" mark to files downloaded from the internet.
If double-clicking does nothing, right-click the file, choose **Properties**,
and tick **Unblock** under *Security* before running it again.

If you prefer to verify the binary before running it, the release also carries
a SHA-256 sidecar (`rustfetch-setup.exe.sha256`) generated by CI. The installer
itself verifies the **payload** (`rustfetch-windows-x86_64.exe`) against its own
`.sha256` sidecar on every run; it aborts and installs nothing if the hash is
missing, malformed, or does not match.

## Command-line options

You can double-click for the defaults, or pass options from `cmd.exe`, a
terminal, or PowerShell:

```
rustfetch-setup.exe [OPTIONS]
```

| Option | Meaning |
| --- | --- |
| `--version vX.Y.Z` | Pin a release tag instead of "latest". A leading `v` is optional (`0.2.8` also works). |
| `--install-dir DIR` | Install into `DIR` instead of `%LOCALAPPDATA%\Programs\rustfetch`. `%VAR%` references are expanded. |
| `--no-path` | Do not add the install directory to the user PATH. |
| `--uninstall` | Remove `rustfetch.exe` and its user PATH entry. |
| `--help`, `-h`, `/?` | Show usage and exit. |

Examples:

```
rustfetch-setup.exe --version v0.2.8
rustfetch-setup.exe --install-dir "%LOCALAPPDATA%\Tools"
rustfetch-setup.exe --version 0.2.8 --install-dir D:\Tools --no-path
rustfetch-setup.exe --uninstall
```

`--uninstall` only removes the file and the PATH entry it added; it leaves any
other files in the install directory alone.

## How it works

1. Downloads `rustfetch-windows-x86_64.exe` from the pinned tag (or the latest
   release) with WinHTTP over HTTPS.
2. Downloads the matching `.sha256` sidecar and computes SHA-256 in pure Rust
   (no OpenSSL, no crypto crate).
3. Writes the verified binary to the install directory.
4. Edits `HKCU\Environment\Path` with `RegSetValueExW` (preserving an existing
   `REG_EXPAND_SZ` type) and broadcasts `WM_SETTINGCHANGE` with `Environment`.

All failures print a step-specific error and exit with a non-zero status;
nothing is installed when verification fails.

## Limitations

- **x86_64 only.** The asset downloaded is
  `rustfetch-windows-x86_64.exe`. arm64 Windows is not supported by this
  installer yet.
- **Requires internet access** to `github.com` over HTTPS (WinHTTP uses the
  system proxy settings).
- **Unsigned**, so SmartScreen may warn on first run (see above).
- **The sidecar is mandatory.** If a release lacks the `.sha256` sidecar the
  installer refuses to proceed; this is stricter than the PowerShell script,
  which treats it as optional.
- **PATH changes apply to new terminals.** The installer broadcasts
  `WM_SETTINGCHANGE`, but already-running applications may need a restart (or
  a sign-out) to pick up the new PATH.
- The binary is a core-module port, not the byte-for-byte Linux parity build;
  see [platform-support.md](platform-support.md).
